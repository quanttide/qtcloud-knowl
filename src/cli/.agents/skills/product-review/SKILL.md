# Product Review Checklist

我反复犯过以下错误。每次评审前逐条检查，**不默念、不跳过**。

## 1. 命名：用户怎么叫它？

- [ ] 这个命名用户第一次见到能猜出意思吗？
- [ ] 还是只有工程师才懂？（反例：`formal`、`new`、`simple`）
- [ ] **测试**：把名字念给非技术同事听，看他能不能解释

## 2. 输出：用户看懂了吗？

- [ ] 输出的每一行，用户都知道它是什么意思吗？
- [ ] 有没有暴露技术术语？（反例：`检测到 3 个未抽象信号`、`跨领域关系覆盖率`）
- [ ] 用户看到报告后知道**自己该做什么**吗？
- [ ] **反例复盘**：v0.0.6 的 audit 输出了工具名和检测结果，业务专家看不懂

## 3. 错误：用户知道接下来怎么办吗？

- [ ] 出错时给的是业务语言还是一堆 traceback？
- [ ] 错误消息包含**原因 + 下一步**，还是只有原因？
- [ ] **反例复盘**：data_home 设成不存在的路径时疯狂报 `PermissionError` 而不是"请确认目录路径"

## 4. 引导：用户知道怎么用下一步吗？

- [ ] 新功能有没有告诉用户"什么时候该用它"？
- [ ] 有没有告诉用户"用了之后下一步做什么"？
- [ ] **反例复盘**：v0.0.8 的 `--mode new` 跑完后用户不知道还可以跑 `--mode formal`

## 5. 成功：用户知道一切正常吗？

- [ ] 全部通过时有正向确认信号吗？还是什么都不输出？
- [ ] **反例复盘**：早期 audit 全部通过时只返回 0，用户不知道是"没跑"还是"全过了"

## 6. 信息量：用户看到的信息够做决策吗？

- [ ] 报告除了指出问题，还告诉用户怎么修了吗？
- [ ] 每个问题都指向具体文件路径和字段了吗？
- [ ] **反例复盘**：v0.0.6 的 audit 报告只说"有问题"，不说"改哪个文件"

## 7. 心智模型：用户的理解和实现一致吗？

- [ ] 用户可能会怎么理解这个功能？和实际行为一致吗？
- [ ] 有没有可能用户理解错了但系统没有提示？
- [ ] **反例复盘**：`extract` 名字让用户以为能自动抽取本体实例，实际只创建了骨架
