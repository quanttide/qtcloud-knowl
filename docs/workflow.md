# 本体结晶循环 (Ontology Crystallization Loop, OCL)

整个工作流分为六个阶段，形成一个螺旋上升的循环。每完成一次循环，本体的形式化程度和与专家认知的对齐程度就提升一个层级。你不需要一次走完所有阶段——每次可以从任意阶段切入。

—

阶段一：知识源准备

输入：非形式化知识文本（章程、手册、日志、会议记录等）

执行者：人

动作：

· 撰写或整理知识源文档
· 为文档标注领域标签（如“组织管理”、“数据治理”），用于后续分领域结晶

输出：带领域标签的原始文本文件

知识工程意义：确定本次知识获取的范围和领域边界。领域的划分不是随意的——它决定了本体中概念空间的初始边界。同一份文本可以在不同领域视角下被多次结晶，产生不同的概念结构。

—

阶段二：AI粗提取（刺激生成）

执行者：AI

动作：

1. 加载该领域已有的形式本体（如果是首次则为空）
2. 对输入文本进行实体和关系提取
3. 生成候选本体片段，输出为一个差异报告：
   · 新增实体（已有本体中不存在的概念）
   · 新增关系
   · 定义有变化的已有实体
   · 每个差异点的置信度标记和AI的定义依据

输出：候选本体差异报告（结构化YAML，包含每个新概念的定义和推理依据）

设计原则：AI不修改已有本体。所有提取结果都以“候选”状态存在，等待专家在下一阶段处理。AI不能因为提取不准确而被“惩罚”——不准确本身就是刺激信号。

—

阶段三：认知对齐（精修的核心）

执行者：人（主导），AI（辅助解释）

子阶段3.1：浏览差异

系统逐条呈现AI提出的新概念或变更。每次只呈现一条，保持认知负荷最小化。

呈现格式：

```
═══════════════════════════════════
  候选概念：技术治理委员会
  类型：职务
  置信度：中
═══════════════════════════════════

AI定义：一个跨部门的决策机构，负责制定技术标准和架构方向。

推理依据：章程第3条提到“技术方向由跨部门会议决定”，
第5条提到“标准需经多方评审”。在组织管理领域，
这种跨部门技术决策实体通常归入“委员会”类型。

当前本体中不存在此概念。

[A] 命名并接受  [L] 听AI详细解释  [D] 丢弃  [S] 跳过
```

子阶段3.2：解释与理解

用户选 L 时，AI展开解释。解释内容聚焦于：

· 这个概念在通用知识体系中的位置
· 为什么AI认为它和用户已有概念不同
· 它的定义依据是什么

子阶段3.3：命名——知识形式化的关键步骤

用户选 A，输入：

· 概念名称（用户自己命名的术语）
· 概念定义（用户自己的表述）
· 与已有概念的关系（可选）

这个动作完成后，概念从AI的“候选”变成用户的“形式化定义”，正式进入本体。

设计原则：

· 每次只处理一条差异，保护注意力
· 不追问，不审问。用户的“跳过”是完全合法的操作
· 命名权完全属于人，AI只提供刺激和参考

输出：更新后的形式本体，包含本轮新结晶的概念

—

阶段四：实例化与校验

执行者：AI为主，人为辅

前置条件：概念空间经过至少一轮结晶，核心概念已由专家命名确认

动作：

1. AI重新扫描知识源文本，提取具体实例
2. 自动将实例匹配到已确认的概念类型下
3. 无法匹配的实例标记为“可能的新概念”，回流到阶段三
4. 匹配结果呈现给专家做最终确认

输出：实例映射表，以及回流到阶段三的未匹配条目

知识工程意义：概念先于实例。当概念空间由专家锚定后，实例提取的准确率大幅提升，校验成本大幅降低。这解决了传统信息抽取中“概念和实例混淆”的核心问题。

—

阶段五：结构完整性检查

执行者：系统自动

动作：

· 检查本体图的结构完整性：孤立节点、断链、缺失反向关系
· 检查知识源覆盖度：哪些概念有实例支撑，哪些还是空壳
· 生成结构健康报告

输出：结构健康报告（缺失列表、覆盖率统计、待补充项）

知识工程意义：这是本体质量控制层。结构完整性检查不依赖人工审查，而是基于图论规则自动完成，确保本体的形式化质量。

—

阶段六：知识应用与回流

执行者：系统自动 + 人

动作：

· 形式本体被版本化保存
· 结构健康报告中的缺失项自动转化为写作待办（“请撰写关于X的章程”）
· 新写作的知识源文本自动触发下一轮结晶循环

输出：写作待办列表，下一轮循环的输入文本

—

完整循环图

```
知识源（章程/手册/日志）
    │
    ▼
[阶段一] 知识源准备（人标注领域）
    │
    ▼
[阶段二] AI粗提取（生成候选本体差异报告）
    │
    ▼
[阶段三] 认知对齐（人浏览→AI解释→人命名结晶）
    │
    ▼
[阶段四] 实例化校验（AI匹配实例→人确认）
    │
    ▼
[阶段五] 结构完整性检查（自动）
    │
    ▼
[阶段六] 知识应用与回流（生成写作待办）
    │
    └──→ 新知识源 → [阶段一]
```

—

知识工程意义上的核心特征

1. 知识获取的触发点：不是文本本身，而是AI通用知识与专家私有知识之间的认知差异
2. 形式化的时机：不是提取时，而是专家命名时
3. 质量控制机制：不是标注更多数据，而是通过概念先于实例、实例自动归类来减少校验成本
4. 迭代驱动：每一轮结晶都提高下一轮的提取精度，因为本体越来越接近专家的认知
