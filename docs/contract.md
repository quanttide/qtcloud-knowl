# 人 / AI / 规则引擎的分工

人的职责不是写 JSON，AI 的职责不是给出正确答案，规则引擎的职责也不是替代人的判断。OCL 的分工按认知层级切分，不按流程阶段切分。

```
高认知层（定义权、裁决权）    →  人
中认知层（刺激、提取、解释）  →  AI
低认知层（校验、执行、一致性）→  规则引擎
```

核心铁律：规则引擎不能替代人做定义，AI不能替人做裁决，人不需要做规则引擎能做的检查。

—

一、人的职责：概念定义者 + 仲裁者

人负责的知识工程动作：

1. 领域锚定
   · 决定知识获取的领域边界（“这次的章程属于组织管理领域”）
   · 这个边界决定后续所有提取的上下文范围
2. 概念命名与定义
   · 这是人最核心的、不可替代的职责
   · 命名意味着：“这个AI提出的概念，在我的体系里叫XXX，定义是XXX”
   · 形式化在这一步完成
3. 认知差异的仲裁
   · 面对AI的候选概念，决定接受、丢弃还是跳过
   · 面对AI的解释，判断“这和我的理解差在哪”
   · 面对规则引擎检测到的结构冲突，做最终裁定
4. 本体演化方向的控制
   · 决定哪些概念需要精修，哪些可以暂缓
   · 决定概念间的关系是否需要调整

人不负责的：

· ❌ 手动提取实体关系
· ❌ 检查孤立节点和结构缺失
· ❌ 校验实例匹配的准确性（只需要确认）
· ❌ 从零写本体骨架

—

二、AI的职责：刺激生成器 + 解释器 + 执行器

AI负责的知识工程动作：

1. 候选本体生成
   · 基于输入文本和已有本体，生成候选实体和关系
   · 输出差异报告：新增、变更、冲突
   · 目标不是准确，而是制造有价值的认知差异
2. 概念解释
   · 当人对候选概念感到陌生时，解释它的定义依据和推理路径
   · 解释的格式是：“我提取这个概念，是因为……在通用框架中它通常指……”
   · 解释的价值是提供对比坐标，帮助人定位自己的理解
3. 实例自动匹配
   · 当概念空间被人锚定后，AI重新扫描文本提取实例
   · 自动将实例归类到已确认的概念下
   · 无法归类的回流到精修阶段
4. 写作待办建议
   · 基于结构健康报告的缺失项，建议人撰写哪些知识源
   · “当前本体中X概念缺少实例，建议补充相关章程”

AI不负责的：

· ❌ 定义概念名称（只能建议，不能决定）
· ❌ 修改已有本体（只能生成候选，不能直接写入）
· ❌ 裁决冲突（只能标记，不能判断谁对谁错）
· ❌ 判断概念的重要性或优先级

—

三、规则引擎的职责：结构完整性的自动化守门人

规则引擎负责的知识工程动作：

1. 结构完整性检查
   · 孤立节点检测：哪个概念没有任何关系连线
   · 断链检测：哪个流程节点没有指向下一步
   · 缺失反向关系：A拥有B，但B没有“被A拥有”的反向声明
   · 概念覆盖度统计：哪些概念有实例支撑，哪些是空壳
2. 一致性校验
   · 新提取的实例是否违反了已有本体的类型约束
   · 同名的两个概念是否在不同的领域下被赋予了矛盾的定义
   · 关系两端的节点类型是否匹配关系定义的约束
3. 实例自动分类
   · 基于已确认的概念空间，对新提取的实例做规则匹配
   · 比如：“张工”这个实例出现在“职务”概念的上下文中，自动归类到“职务”下
   · 这是确定性规则，不依赖AI
4. 版本与变更管理
   · 本体每次更新后自动版本化
   · 记录变更历史：谁、何时、修改了什么
   · 支持回滚
5. 写作待办自动生成
   · 当结构完整性检查发现缺失时，自动生成待办条目
   · 不需要AI建议，而是基于规则：“概念X缺少实例 → 待办：撰写X相关章程”

规则引擎不负责的：

· ❌ 理解语义（不判断“这个概念有没有用”）
· ❌ 生成新概念（只能检查已有概念的完整性）
· ❌ 裁决语义冲突（只能标记“A和B定义矛盾”，不判断哪个定义是对的）

—

四、分工协作图

```
知识源文本
    │
    ▼
[AI] 候选本体生成 ──→ 差异报告
    │
    ▼
[人] 浏览差异 → 听解释 → 命名/丢弃/跳过
    │
    ├──→ 命名 → 概念进入形式本体
    │
    ▼
[规则引擎] 自动检查结构完整性
    │
    ├──→ 孤立节点告警 → [人] 决定补充或删除
    ├──→ 概念覆盖度报告 → [规则引擎] 自动生成写作待办
    │
    ▼
[AI] 实例自动匹配 ──→ [规则引擎] 校验类型约束 ──→ [人] 确认
    │
    ▼
形式本体更新，版本化保存
```

—

五、这一分工的本质

· 人掌握认知权：定义、命名、仲裁。这是知识工程中不能被替代的“形式化”动作。
· AI作为信息源：从通用知识中提取信号，制造认知摩擦，加速人的形式化过程。AI不是答案提供者，是问题制造者。
· 规则引擎作为质量网：用确定性规则兜底，让人的注意力只花在语义和认知层面，不花在结构完整性这种可自动化的问题上。

三者各司其职，不相互替代，也不相互甩锅。本体质量的最终责任在人，但到达人面前的问题已经被AI和规则引擎过滤了两轮。
